# 2026-10-29 — audio.cpp builds come from the Atomic fork through conf's mirror, as the engine-builds row audio-cpp

- **Context:** upstream audio.cpp releases `vX.Y.Z` roughly weekly, mostly from one author, with prebuilt archives for macOS, Windows x64 and Ubuntu x64 only — none for Linux or Windows arm64 — and without eSpeak-ng, which Kokoro needs (every Kokoro speech request answers `Could not load eSpeak-ng`). sd.cpp went the same way: first conf mirrored upstream (2026-09-10), then the Atomic fork built every archive (ADR 2026-10-07, the core owns sd.cpp and MLX engine builds).
- **Decision:** `audio-cpp` is an `engine-builds` engine. `AtomicBot-ai/audio.cpp` builds every archive from an unmodified upstream tag plus `atomic/patches/` (`release-atomic.yml`), named `audio-<tag>-bin-<backend>.zip`, flat, with `-DAUDIOCPP_DEPLOYMENT_BUILD=ON` and, by default, eSpeak-ng linked in statically (`-DAUDIOCPP_STATIC_ESPEAK=ON`). conf's `mirror-audiocpp.yml` signs and re-hosts them and writes `backends/audiocpp-manifest.staging.json`; `audiocpp-approve.yml` moves a checked tag to the live `backends/audiocpp-manifest.json`, which the core reads (`ATOMIC_AUDIOCPP_MANIFEST_URL` overrides it). The manifest has sd.cpp's shape, so the core parses both with one parameterised ggml release parser (`parseGgmlReleaseManifest` with per-engine tag pattern and default repository). Tags are `vX.Y.Z` or a rebuild `vX.Y.Z-a<rev7>`, ordered by version with the rebuild above the bare tag. The host's build comes from sd.cpp's ladder without ROCm; failed rungs are remembered per engine (`<data>/audio/failed-backends.json`). The probe runs `--version` (the binary is audio.cpp) and, for a GPU build, `--list-devices` (it sees a GPU), so a Vulkan build on a machine without a driver moves the install down the ladder. The `backends:` line of `--version` is not trusted, because a build that loads its GPU backend at run time lists only `cpu` there.
- **Consequences:** until the fork's first release is mirrored and approved, conf has no live audio.cpp manifest and the catalog answers "manifest unavailable"; the staging manifest can point at upstream's own archives to bootstrap (no eSpeak-ng, no arm64). With eSpeak-ng linked in, the fork's binaries are GPL-3.0-or-later combined works; each archive carries `licenses/espeak-ng/` with the eSpeak-ng source, and the fork is public. Whether Atomic Chat ships that build is a product decision still open (`static_espeak: false` builds archives without it, and Kokoro then cannot speak). Intel Macs get no build: the shared ladder offers none on x64 macOS. Windows CUDA archives are large (the cu12 companion carries cudart and cuFFT).
