# 2026-10-06 — vLLM runs `vllm serve` with its KV cache in bytes and its memory share sized by core

- **Context:** change `add-vllm-runtime` adds vLLM (`docker.io/vllm/vllm-openai:v0.31.0-cu129`, pinned by digest in `runtimes/vllm.json`) as a second managed engine. vLLM V1 sizes its memory as a share of the card's *total* memory (`--gpu-memory-utilization`) and, before it starts, refuses to run when the card's free memory is below that share — so a fixed share fails on any desktop whose card holds a display and a browser, which is exactly the user TensorRT-LLM does not reach. vLLM also sends usage stats and may reach Hugging Face by default.
- **Decision:** the `vllm` adapter (`src/runtime/vllm/adapter.ts`) runs `vllm serve <model> --served-model-name <id> --host 0.0.0.0 --port 8000 --max-model-len <ctx> --max-num-seqs <n> --kv-cache-memory-bytes <B> --gpu-memory-utilization <U> --limit-mm-per-prompt {"image":0,"video":0}`, with `--enforce-eager` when CUDA graphs are off (`auto`: below 12 GiB of card), `--kv-cache-dtype fp8` on compute capability 8.9+, and the family's parsers; never `--trust-remote-code`, `--enable-log-requests` or `--api-key`. Its env switches usage stats off and Hugging Face offline and puts every compile cache under the engine cache. `B` and `U` are core's (`src/runtime/vllm/memory.ts`): `B` = the KV token limit, else context × requests (two contexts on unified memory), × the model's per-token KV bytes at the KV precision; `U` = `min(0.95, (free − 512 MiB) / total)` from the card re-probed right before the container. The managed-text lifecycle now runs `beforeCreate` once right after `stopPrevious` and hands what it answers to `buildLaunch` as the engine's `plan`, so the share is measured after the previous sessions stopped. Weights + KV + ~2 GiB of engine overhead are checked against the free memory before any container, by the same rule as `POST /models/vllm/check`.
- **Consequences:** vLLM's own start check passes by construction on a partly used card; a model that does not fit is refused with numbers before a container exists. The overhead (2 GiB), the margin (512 MiB), the readiness timeout (10 min + 20 s/GiB), the stage markers and the exit wording are first estimates from vLLM 0.31's source; the live run of task 6.1 (`test/live/vllm.test.ts`) confirms or changes them with the numbers recorded in the change's rulings.
