# 2026-09-17 — Report download stages as their own event, and answer free disk space inside the data folder

- **Context:** The app's image-generation line made a download say what it is waiting on (its issue #290): the preflight `HEAD` and the first `GET` each run a five-step backoff ladder (1+2+4+8+16 s) that emitted nothing, so a download that could not reach the server looked like one that had not started. In Rust the stage rides on the task's `download-<taskId>` event as `{transferred:0,total:0,stage}`. Backend installs on the core-migration line go through this core's `Downloader`, which has the same silent ladders. The app's relay pins the `download:progress` payload to `{transferred,total}` exactly when it re-emits the legacy event (`relay.rs` `legacy_event_for` and its test), and an older relay forwards any `download:progress` frame as progress. Separately, the image-generation frontend asks `plugin:llamacpp-upstream|available_disk_space` before downloading an engine or a model, a command the core migration deleted.
- **Decision:** A new event `download:stage` `{taskId, stage:{kind:'connecting'|'retrying', attempt, maxAttempts}}`, never a `download:progress` frame: a 0/0 progress frame would rewind the bar in any consumer that does not know the field, and `percent` on it would be a lie. `connecting` (attempt 0) is reported only when a preflight `HEAD` is actually made; `retrying` (attempt n+1) before each backoff wait of the preflight ladder and of the first-request ladder; the mid-stream reconnect loop stays silent, as in Rust. The app's relay maps the event back onto `download-<taskId>` with the Rust payload, so the webview sees one shape from both download paths. Free space is a control route, `POST /atomic/v1/disk/available {path?}` → `{bytes: number|null}`: the path travels in the body (absolute paths carry user names), must resolve inside the data folder, defaults to it, and reuses the downloader's own probe.
- **Consequences:** An app build that predates the mapping ignores the unknown event instead of mis-rendering it. Consumers must treat a stage as a status change, never as progress. The disk route cannot be used to probe arbitrary volumes; callers that need another volume (a custom image output folder) do not get an answer from the core.
