# 2026-10-23 — Loopback inference streams use raw-socket HTTP

- **Problem:** On macOS arm64 with the shipped Bun 1.3.10 core, an image conversation could remain
  `Working...` after the inference server finished. The core delivered the initial 212-byte
  role-only SSE event, then neither body deltas nor EOF. The same dialogue completed through a
  transparent TCP relay. Text-only control conversations completed. Sending `Connection: close`
  did not fix the image follow-up. A small, model-free delayed-SSE fixture with a 1.2 MB POST and
  exposed GC reproduced a stalled `node:http` response; the existing raw-socket client completed
  every frame under the same collection pressure. Keeping the `ClientRequest` alive separately
  did not fix the real-image reproduction, so this does not assert a particular collected object
  or an identified Bun internal implementation defect.
- **Decision:** Plain HTTP requests whose URL names a loopback host use `createPolicyFetch` from
  downloads, with its direct raw-socket HTTP/1 parser. Reuse its abort, framing, backpressure, and
  manual-redirect behavior rather than add a second parser or runtime dependency. The response is
  exposed as a Node `Readable` backed by an explicit web reader, whose destruction cancels even a
  pending body read immediately. Cloud and TLS upstreams keep
  their existing `node:http` / `node:https` route. Add an optional direct dial timeout to the shared
  policy so the inference caller retains its configured connect deadline; do not impose a new
  whole-request or prefill timeout.
- **Behavior:** Request JSON, assistant instructions, clock metadata, model sampling, image input,
  and KV-cache behavior are unchanged. Each local upstream request has its own connection, as the
  raw parser requires. Responses support Content-Length, chunked and connection-close framing.
  Cancellation still closes the upstream and rejects the response reader. Abort errors are handled
  even when a consumer has not attached yet. The original download policy defaults stay unchanged.
- **Evidence:** `test/runtime-compat/http-stream-gc.test.ts` exercises repeated delayed responses
  under `bun --expose-gc test` and the same fixture under Node, plus mid-body cancellation. The
  pre-change code failed this GC regression with `SSE stopped before EOF`. The fixture contains
  generated bytes only; no model, personal assistant prompt, screenshot or conversation is needed.
  The live installation and image-dialogue verification are tracked separately from source tests.
- **Limits:** The evidence isolates the failure to Bun's HTTP compatibility path under GC; it does
  not identify the exact object or native runtime instruction responsible. This is a transport
  workaround with a pinned regression, not a model or prompt-quality change.
- **Files:** `src/server/public/wire.ts`, `src/downloads/proxy-fetch.ts`,
  `test/runtime-compat/http-stream-gc.test.ts`.
