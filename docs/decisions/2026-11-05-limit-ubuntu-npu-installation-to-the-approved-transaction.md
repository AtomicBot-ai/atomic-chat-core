# Limit Ubuntu NPU installation to the approved transaction

The elevated helper derives its commands from the selected Ubuntu recipe. It rechecks the running kernel, PCI identity, system mutability and runtime account. It verifies each exact version, package identity, archive path, size and SHA-256 against a single repository's authenticated index. Its temporary sources and keyrings expire with the operation. A missing version or an extra dependency in the simulated transaction requires a new plan. Only the verified local archives reach dpkg. This keeps a general upgrade, kernel swap or an unplanned resolver download outside the operation. See the [APT archive authentication model](https://manpages.ubuntu.com/manpages/noble/man8/apt-secure.8.html).

Both reviewed DKMS archives restrict builds to kernels 6.17, 6.18 and 6.19. The helper pins their hashes, requires a present IOMMU group and matching headers, and checks that the selected module is the DKMS output for the running kernel. A working inbox driver can still use an account-only plan on other qualified kernels. This implementation blocks automated module installation under Secure Boot pending a qualified signing and enrollment procedure. The pinned candidate's NPU6 register table selects the NPU4 firmware directory for PCI revision 20. The helper checks the actual firmware link and its versioned target in the archive. The r1/r2 Linux engine ships XRT ABI 2, so it uses its bundled libraries. System XRT recipes must match the selected build and provide ABI 2 libraries.

Device access uses a udev rule for one PCI parent and one numeric UID. Interactive processes use a limits.d entry for that account. Service limits use a drop-in for the selected unit. The user manager must already have a sufficient hard limit and its drop-in is written as the target user. The helper never restarts the runtime or establishes readiness from its root context. A new runtime process verifies the resulting permissions, memory limit and XRT device. Native qualification of both Ubuntu versions remains a release gate.
