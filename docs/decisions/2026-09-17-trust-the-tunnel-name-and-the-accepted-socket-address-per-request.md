# 2026-09-17 — Trust the live tunnel name and the accepted socket's address as a per-request group

- **Context:** The public `/v1` listener refuses a `Host` header that is neither loopback nor in the configured trusted hosts (`isValidHost`). That is the DNS-rebinding guard, pinned byte for byte by the `proxy-http` fixtures. The app's Remote & LAN feature brings two callers whose `Host` nobody could have typed in advance: a Cloudflare quick tunnel, whose `<words>.trycloudflare.com` name exists only once `cloudflared` has printed it and is new on every start, and a LAN client dialling this machine's own address, which changes with the network. In the app this lived in the Rust proxy (`dynamic_hosts.rs`); on the core-migration line the proxy no longer serves desktop, and the core's listener captures `trustedHosts` by value at start and treats it as part of its identity (`publicOptionsCompatible`), so an incompatible restart is a `CORE_ALREADY_RUNNING` conflict and a restart would drop every connection anyway.
- **Decision:** `DynamicTrustedHosts` holds the tunnel name; `groupFor(localAddress)` answers the extra group for one request — the tunnel name while one is set, plus the local address of the accepted socket when it is neither loopback nor unspecified (IPv4-mapped IPv6 unmapped, a zone id dropped, IPv6 bracketed because that is the only spelling `isValidHost` strips a port from). `handlePublicRequest` appends that group to a per-request copy of the configuration, so `preflight`, `gate`, `corsHeaders` and the exchange read it unchanged. `isValidHost`, `gates.ts` and `publicOptionsCompatible` are not touched; the dynamic group is never part of the listener's identity. Only a bare hostname can become the tunnel name: anything else — `*` above all — clears it.
- **Why the rebinding guard is not weakened:** a rebinding page makes the browser send the *attacker's* domain in `Host`; it cannot make that header equal the tunnel's real public name, which only Cloudflare's edge routes to this machine, nor the literal address of the socket the request arrived on, because a rebinding `Host` is a name, never the victim's IP literal. A loopback bind gains nothing: its socket address is loopback, which adds no entry. The group never contains `*`. Non-browser LAN clients could always send `Host: localhost`; the Host gate only ever constrained browsers, and the API key remains the access control. CORS still reflects only origins whose host is trusted.
- **Consequences:** deliberate behaviour change, same as the app's: once the user binds the server to a LAN address or `0.0.0.0`, a LAN client that dials the machine's address passes the Host gate without a Trusted Hosts entry. The group is computed per request, not per connection, because a keep-alive connection outlives a tunnel. The existing `proxy-http` fixtures replay unchanged with an empty group.
