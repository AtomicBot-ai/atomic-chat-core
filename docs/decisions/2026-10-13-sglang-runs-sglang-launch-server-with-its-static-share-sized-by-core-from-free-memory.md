# 2026-10-13 — SGLang runs `sglang.launch_server` with its static share sized by core from free memory

- **Context:** change `add-sglang-runtime` adds SGLang (`docker.io/lmsysorg/sglang:v0.5.21`, pinned by digest in `runtimes/sglang.json`) as the third managed engine — the first to come in through the registry of ADR 2026-10-06 ("Managed engines are registered specs") with no change to shared code. SGLang sizes its budget from the memory it finds free at start-up, once its CUDA context exists: it keeps `--mem-fraction-static` of it for weights and KV cache, and the rest is its room for activations and CUDA graphs. Its own default share is computed from the card's *total* memory, so on a card a desktop already holds part of, that room comes out smaller than SGLang meant. Three things core read in SGLang v0.5.21's source changed the plan's first draft: its `--language-model-only` flag accepts only three architectures, none of the descriptor's; `--preferred-sampling-params` never reaches the OpenAI path, which fills every sampling value (and `max_new_tokens: None`) before merging them; CUDA graphs are configured per phase, and `--disable-cuda-graph` is deprecated.
- **Decision:** the `sglang` adapter (`src/runtime/sglang/adapter.ts`) runs `python3 -m sglang.launch_server --model-path <model> --served-model-name <id> --host 0.0.0.0 --port 30000 --context-length <ctx> --max-running-requests <n> --mem-fraction-static <f>`, then only what differs from SGLang's own values: `--max-total-tokens`, `--chunked-prefill-size`, `--disable-radix-cache`, `--dtype`, `--random-seed` from the settings; `--cuda-graph-max-bs-decode <n>` for `cuda_graphs: auto`, both `--disable-{decode,prefill}-cuda-graph` for `off`; `--kv-cache-dtype fp8_e4m3` on compute capability 8.9+; the family's parsers; and `--json-model-override-args {"language_model_only":true}` for a multimodal checkpoint — the checkpoint's own "text only" declaration, which every class honours (no multimodal reservation, media refused). Never `--trust-remote-code`, `--log-requests`, `--api-key`/`--admin-api-key` or `--enable-metrics`. Its env keeps Hugging Face offline, sets `SGLANG_MAX_NEW_TOKENS_LIMIT` to the output setting (SGLang's scheduler caps a chat request that names no output at it and then at the room the context has left, refusing nothing; a completions request that names none keeps OpenAI's 16), and puts every compile cache — SGLang's own and its JIT kernels', Triton's, inductor's, FlashInfer's, CUDA's — under the engine cache. The gateway caps an explicit `max_tokens` and writes the sampling defaults a request does not set. `f` is core's (`src/runtime/sglang/memory.ts`) unless the `mem_fraction_static` setting fixes it: `(F − R) / F`, clamped to [0.5, 0.95], from the card re-probed right before the container, `R` = 2 GiB with graphs, 1.25 GiB without — so SGLang keeps about `R` whatever other processes took; on unified memory `(min(F, half the host) − R) / F`. Within its share SGLang sizes the KV cache itself, hybrid models included. Weights + an estimate of the KV cache + ~2 GiB of overhead + 512 MiB are checked against the free memory before any container, by the same rule as `POST /models/sglang/check`. Ready only after one generated token. The provider lists that named managed engines one by one (`server/public/responses.ts`, `config/paths.ts`, the `registry()` overloads) now read `MANAGED_PROVIDER_IDS` in `./contracts`, and the registry refuses at startup an engine missing from it.
- **Consequences:** SGLang starts on a partly used card with the reserve it was sized for; a model whose weights leave no room for the KV cache fails within seconds, classified as out of memory with SGLang's share and the least that would do; a model that does not fit is refused with numbers before a container exists. A fourth managed engine touches the declarative provider lists and `MANAGED_PROVIDER_IDS`, not the code that branched on names. The reserve, the overhead, the margins, the CUDA graph mode `auto` (prefill graphs stay SGLang's), the readiness timeout (10 min + 20 s/GiB), the stage markers and the exit wording are first estimates from SGLang v0.5.21's source; the live run of task 4.1 (`test/live/sglang.test.ts`) confirms or changes them with the numbers recorded in the change's rulings.
