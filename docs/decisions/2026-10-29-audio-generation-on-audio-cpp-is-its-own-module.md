# 2026-10-29 — Audio generation on audio.cpp is a module of its own: one server per model, a config the core writes, cancel by stopping the server

- **Context:** the app's Audios studio (speech, music, sound effects; dev builds only, app ADR 2026-10-27) has no engine. audio.cpp (`0xShug0/audio.cpp`, Apache-2.0, ggml) serves TTS on `POST /v1/audio/speech` and music and effects on a synchronous `POST /v1/tasks/run` from `audiocpp_server`. A spike on upstream v0.9.3 (fixtures in `test/fixtures/audiocpp/v0.9.3/`) found: models are declared only in the server's `--config` file (`POST /v1/models/load` needs `--ui-management`, the build with downloads we do not ship); with `lazy_load: false` the server listens only once the model is loaded; there is no job or progress API; a client that disconnects from a JSON request does not stop the run; request errors come back as HTTP 500 `{"error":{"message"}}`; `--backend` defaults to `cuda` and the embedded web UI is on by default; each GGUF package is unpacked under `$TMPDIR`.
- **Decision:** `src/audio/` is a module of its own beside `src/diffusion/`, with its own camelCase contract (`src/contracts/audio.ts`, `AUDIO_ERROR_CODES`, events `audio:{state,job,error}`) rather than another value of `MediaKind` or `DiffusionModality`. A load writes `<data>/audio/run/*.json` with one model (`lazy_load: false`, `max_loaded_models: 1`, `idle_unload_ms: 0`; the core owns idle unload) and starts `audiocpp_server --config … --no-ui --host 127.0.0.1 --port … --backend …` from the build folder, with `TMPDIR` under `<data>/audio/tmp`; ready is `/health` plus `/v1/models` naming our id, family and task as loaded. Another model is another server. A load names a file under `<data>/audio/models` and the family, task and options to serve it as — the client's catalog supplies them, as diffusion loads carry the family's defaults; the core never downloads a model (ADR 2026-10-15). One job at a time: speech goes to `/v1/audio/speech`, music and effects to `/v1/tasks/run`; progress is phases only (`queued`, `loading`, `generating`, `saving`); the clip is `<outputDir>/<jobId>.wav` with a `<jobId>.json` recipe, default `<data>/audios`. Cancel aborts the request, stops the server and keeps the spec, so the next job starts it again. A session on a GPU backend is an exclusive occupant of `core/gpu-residency.ts` like image generation: a chat load evicts an idle audio model and gets `GPU_BUSY` while a clip generates (ADR 2026-10-08); a CPU session claims no card. The control API is `/atomic/v1/audio/*`; builds are the engine-builds row `audio-cpp` (ADR 2026-10-29, audio.cpp builds come from the Atomic fork).
- **Consequences:** switching models restarts the server (seconds; the first Metal start compiles kernels once). Long music shows no percentage. A cancel always costs a restart. Small TTS models cannot stay resident beside a chat model on the same GPU yet — a follow-up for the residency rule. A request with no `durationSec` gets Stable Audio's default of 120 s, so clients should always send one. Models whose base variant needs a voice to clone (Qwen3-TTS Base) are recognised from the loader's own trace and refuse a speech job without `voiceRef` before the engine does.
