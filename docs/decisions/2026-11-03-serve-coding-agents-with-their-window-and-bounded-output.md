# 2026-11-03 — Serve coding agents with their window, bounded output and two shared-KV slots

- **Context:** QA of desktop 2.3.2 on Qwen3.5 4B (llama.cpp b12019) found every terminal agent failing on a small local model. No agent was told the window: Claude Code assumed 200K, Codex 272K, Kilo/OpenCode turned compaction off, and an overflow on `/v1/messages` came back in llama.cpp's own wording, which Claude Code does not recognise. One slot (`--parallel 1`) made each side request (titles, classifiers) wait in front of the turn; `n_predict -1` with no reasoning budget let a thinking model write 20,000 tokens for a session title; vLLM/SGLang defaulted to an 8K window that refuses every 13–27K agent prompt. Mid-conversation system messages, hoisted into `system`, rewrote the prompt prefix and forced a full reprocess on hybrid and sliding-window models.
- **Decision:** The server tells clients the window and answers its overflow in their terms: `/v1/models` carries `context_length` and `meta.n_ctx` per local model (read from the session's `/props` once per load); `/v1/messages` maps a llama.cpp overflow to `400 prompt is too long: N tokens > M maximum`; an Anthropic request that asks for no thinking gets `enable_thinking: false`; mid-conversation system messages stay in place as `<system-reminder>` user text; the chat-completions fallback keeps `max_tokens`; Codex's MCP namespace tools are flattened and mapped back. Engine defaults favour agents: llama.cpp runs 2 slots with a unified KV cache (`-kvu`, same memory, fit math no longer multiplies the KV by the slot count), `n_predict` 0 means automatic (16384, never above the window), a default reasoning budget of 8192, explicit continuous batching, `--cache-ram` 1–2 GiB on machines with ≤ 16 GiB; 32K is the default window where memory allows (MLX, fit off); vLLM/SGLang pick the widest of 64K×2 … 8K×1 the memory plan passes. Stored values still at an old default move once (`state.default_migrations`). Agent writers receive the window (`ConfigureInput.contextLength`, filled by `atomic-chat launch` from `/props`).
- **Consequences:** Agents compact before the server refuses and do not starve behind their own side requests. One long prompt can still fill the shared pool and fail a concurrent slot. A thinking model's reasoning stops at 8192 tokens unless the user raises the budget; replies stop at 16384 unless the client asks for more. A user who deliberately chose an old default is moved once. The app must vendor the changed schemas (`llamacpp-upstream`, `llamacpp`, `atomic-prism`, `vllm`, `sglang`) together with the release that ships them: with an older core, `parallel 2` without `-kvu` would halve each slot's window. Not yet live-verified on real engines.
